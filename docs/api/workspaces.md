# API — Workspaces

Workspaces are a top-level resource, independent of the `admin` namespace. A workspace contains zero or more organizations via a many-to-many join table. Scopes use the `workspaces:*` prefix (defined in `api/config/scopes/workspaces.json`).

**Base path:** `/api/v1/workspaces`

**Authorization:** all endpoints require `Authorization: Bearer {access_token}`.

---

## Scope catalog

| Scope | Purpose |
|-------|---------|
| `workspaces` | Umbrella — grants everything below |
| `workspaces:read` | Read workspaces, organizations, and memberships |
| `workspaces:write` | Create/update workspaces and memberships |
| `workspaces:delete` | Delete workspaces and memberships |

`super:admin` also grants access to every endpoint below.

---

## Workspace CRUD

Resource template: `/{res:workspaces}` — the request URL contains the literal `{res:workspaces}` segment.

| Method | Path | Scope (OR) | Purpose |
|--------|------|-----------|---------|
| GET | `/api/v1/workspaces/{res:workspaces}` | `workspaces:read`, `workspaces`, `super:admin` | List |
| GET | `/api/v1/workspaces/{res:workspaces}/{id}` | `workspaces:read`, `workspaces`, `super:admin` | Read one |
| POST | `/api/v1/workspaces/{res:workspaces}` | `workspaces:write`, `workspaces`, `super:admin` | Create |
| PATCH | `/api/v1/workspaces/{res:workspaces}/{id}` | `workspaces:write`, `workspaces`, `super:admin` | Partial update |
| PUT | `/api/v1/workspaces/{res:workspaces}/{id}` | `workspaces:write`, `workspaces`, `super:admin` | Replace |
| DELETE | `/api/v1/workspaces/{res:workspaces}/{id}` | `workspaces:delete`, `workspaces`, `super:admin` | Delete |

**Request body (POST / PATCH / PUT):**

```json
{
  "title": "My Workspace",
  "description": "Optional free-text description",
  "is_active": true
}
```

**Response (single):**

```json
{
  "id": "<uuid>",
  "title": "My Workspace",
  "description": "Optional free-text description",
  "created_at": "YYYY-MM-DD HH:MM:SS",
  "is_active": true
}
```

## Workspace Organization (membership) CRUD

The `workspace_organizations` table links a workspace to zero or more organizations. Adding or removing a membership is done via this resource.

| Method | Path | Scope (OR) | Purpose |
|--------|------|-----------|---------|
| GET | `/api/v1/workspaces/{res:workspace_organizations}` | `workspaces:read`, `workspaces`, `super:admin` | List all memberships |
| GET | `/api/v1/workspaces/{res:workspace_organizations}/{id}` | `workspaces:read`, `workspaces`, `super:admin` | Read one |
| POST | `/api/v1/workspaces/{res:workspace_organizations}` | `workspaces:write`, `workspaces`, `super:admin` | Add an organization to a workspace |
| PATCH | `/api/v1/workspaces/{res:workspace_organizations}/{id}` | `workspaces:write`, `workspaces`, `super:admin` | Partial update |
| PUT | `/api/v1/workspaces/{res:workspace_organizations}/{id}` | `workspaces:write`, `workspaces`, `super:admin` | Replace |
| DELETE | `/api/v1/workspaces/{res:workspace_organizations}/{id}` | `workspaces:delete`, `workspaces`, `super:admin` | Remove an organization from a workspace |

**Filtering:** use `?filter[@exact:workspace_id]=<uuid>` to fetch memberships for a specific workspace.

**Request body (POST):**

```json
{
  "workspace_id": "<workspace-uuid>",
  "organization_id": "<organization-uuid>",
  "is_active": true
}
```

Duplicates are rejected by the unique index on `(workspace_id, organization_id)` — the response is HTTP 500 with message `UNIQUE constraint failed: workspace_organizations.workspace_id, workspace_organizations.organization_id`.

**Response (single):** includes hydrated `workspace` and `organization` sub-objects via the entity's `m2o` relations:

```json
{
  "id": "<uuid>",
  "workspace_id": "<uuid>",
  "organization_id": "<uuid>",
  "created_at": "YYYY-MM-DD HH:MM:SS",
  "is_active": true,
  "workspace":    { "id": "<uuid>", "title": "...", ... },
  "organization": { "id": "<uuid>", "title": "...", "description": "...", ... }
}
```

## Organizations (read-only, for selectors)

Read-only endpoints exposing the organization list. Registered under the workspaces parent so the workspace UI can populate an "add organization" picker without requiring additional scopes. Full organization management is out of scope.

| Method | Path | Scope (OR) | Purpose |
|--------|------|-----------|---------|
| GET | `/api/v1/workspaces/{res:organizations}` | `workspaces:read`, `workspaces`, `super:admin` | List organizations |
| GET | `/api/v1/workspaces/{res:organizations}/{id}` | `workspaces:read`, `workspaces`, `super:admin` | Read one |

**Response (single):**

```json
{
  "id": "<uuid>",
  "title": "Default Organization",
  "description": "Auto-seeded default organization",
  "created_at": "YYYY-MM-DD HH:MM:SS",
  "is_active": true
}
```

A default organization row with id `00000000-0000-0000-0000-000000000001` is seeded by migration `19_04_2026_11_00_54.sql` to provide a starting option for new workspaces.
